# Out-of-Scope Decisions

Read the relevant OpenSpec specifications and archived change designs before revisiting a request. Rejection is a user decision, not a deduction from a missing implementation.

When the user rejects an enhancement, record the concrete behavior, rationale and scope in the relevant change's Non-Goals or Decisions. Reference earlier decisions when they actually apply. Keep the record short and explain non-obvious constraints.

An already implemented request is not a rejected feature; point to its actual implementation and evidence. A temporary scheduling decision is not a permanent scope restriction.

If the user reopens a decision, create or update the appropriate change and preserve the historical context. Do not silently erase archived design decisions or automatically reopen external issues.
