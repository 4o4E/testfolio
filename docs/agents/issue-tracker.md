# 事项管理：本地 OpenSpec

本项目的事项以 openspec/changes/ 中的变更目录及 tasks.md 管理。需要发布需求、拆分任务、认领工作或记录状态的技能先读取本文件。GitHub 承载公开代码与版本；创建外部 Issue、PR 或发送评论需要用户明确授权。

“发布规范”表示更新对应变更的 proposal.md、specs/ 和 design.md；“发布任务”表示更新 tasks.md 中有稳定编号的复选项。每项任务记录目标行为、阻塞任务及验证条件，任务依赖只记录真实的先后关系；需要详细说明时放在本变更目录内并从任务链接过去。

状态使用 docs/agents/triage-labels.md 的词汇，记录在 proposal.md 的状态说明；完成情况以 tasks.md 复选项为准。尚待用户决定的事项保留为待处理，不写成已确认。

“获取事项”表示读取指定变更或任务及其关联设计。对于大规模规划，地图和决策放在该变更目录内；完成并验证后同步规范、归档变更，不另建平行事项目录。拒绝的方案及依据也记录在相关 design.md 的 Non-Goals 或 Decisions 中。
