# 构建缓存及增量更新

## Why
维护者更新代码时应复用既有构建结果，使用者更新服务时应复用本机已有镜像层。需要减少依赖安装和前端生产打包的重复工作，同时保留实际容器检查及版本发布约束。

## What Changes
- 使用 GHCR 持久构建缓存，隔离主线检查与版本发布的缓存写入，拉取请求只读取。
- 前端生产包在原生构建平台生成一次，供两个运行架构使用；前端独立检查保留 lint 和类型检查。
- 固定基础镜像与完整 Python 依赖，代码、网页和许可证分别保存为可复用镜像层。
- 明确版本下载一次后启动、普通重启不访问仓库的 Compose 使用方式。

## Capabilities

### Modified Capabilities
- `publishing`：构建缓存复用、可信写入及已下载版本的离线重启。

## Impact
修改 Dockerfile、CI、Python 依赖声明／锁文件、Compose 示例和部署文档；不修改应用功能、接口或数据库，不切换现有实例，不修改 Docker 全局代理，不发布新的正式版本。
